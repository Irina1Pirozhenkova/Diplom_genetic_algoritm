# Program: модель этногенеза на базе генетического алгоритма

## Как запускать

```powershell
python -m program run
python -m program render --config best_parameters/best_config.json
python -m program search
```

## Что делает программа

Проект моделирует этногенез как стохастический эволюционный процесс.  
В модели есть популяция особей, каждая особь несёт вектор призваний, а развитие этноса во времени определяется:

- отбором;
- кроссовером;
- мутациями;
- ограничениями среды;
- наблюдаемой кривой пассионарности, которую мы строим по поколениям.

Финальная прикладная версия программы использует фиксированную размерность `I = 4`, то есть четыре координаты призваний:

- военная сила;
- экономическая самостоятельность;
- успешность внешней торговли;
- развитость культуры и религии.

Модель устроена так, чтобы на выходе давать кривую, похожую по форме на графики из статьи и на характерный график Гумилёва: подъём, главный горб, волны на разных фазах и затухающий хвост около нуля.

## Основные режимы работы

### 1. Обычный запуск на лучших параметрах

```powershell
python -m program run
```

Далее выбрать:

```text
1
```

Программа возьмёт уже найденные лучшие параметры из файла `best_parameters/best_config.json` и перестроит стандартный набор графиков в папке `best_parameters/`.

Если интерактивный режим не нужен, можно сразу выполнить:

```powershell
python -m program render --config best_parameters/best_config.json
```

### 2. Пакетный запуск через планировщик задач

```powershell
python -m program run
```

Далее выбрать:

```text
2
```

После этого можно указать:

- короткое имя сценария, например `scenario_1`;
- или полный путь к JSON-файлу сценария.

Примеры:

```text
scenario_1
scenario_2
scenario_3
```

Можно запускать и без интерактивного выбора:

```powershell
python -m program run --scenario scenario_1
python -m program run --scenario scenario_2 --workers 3
python -m program run --scenario scenarios/scenario_3.json
```

## Какие графики строятся

Для одного конфига программа строит шесть итоговых графиков.

### 1. `passionarity_base.png`

Базовая кривая суммарной пассионарности.

### 2. `passionarity_E.png`

Сравнение трёх кривых на одном графике:

- базовое значение `E`;
- `E x3`;
- `E /3`.

### 3. `passionarity_K.png`

Сравнение трёх кривых на одном графике:

- базовое значение `K`;
- `K x3`;
- `K /3`.

### 4. `shock_1072.png`

Базовая кривая с поздним резким изменением среды.

### 5. `shock_647.png`

Базовая кривая с ранним резким изменением среды.

### 6. `criterion_C_base.png`

График общесистемного критерия эффективности `C(t)`.

## Что показывается в легендах

Легенды рисуются прямо внутри области графика, а не сбоку. В них выводятся основные параметры эксперимента:

- `I`;
- `n`;
- `P0`;
- `E`;
- `K`.

Для графиков сравнения по `E` и `K` в легенде используется тот же цвет, что и у соответствующей линии на графике.

## Папки результатов

### `best_parameters/`

Эта папка хранит обычный одиночный режим:

- `best_config.json`;
- `search_result.json`;
- `experiment_scenarios.json`;
- все 6 PNG-графиков.

### `scheduler_runs/`

Эта папка хранит результаты пакетного режима:

```text
scheduler_runs/
  YYYY-MM-DD_HH-mm-ss_<scenario_name>/
    scenario.json
    manifest.json
    run_01_<name>/
    run_02_<name>/
    run_03_<name>/
```

Внутри каждой папки прогона лежат:

- `effective_config.json`;
- `experiment_scenarios.json`;
- все 6 PNG-графиков.

## Как устроен JSON-сценарий

Сценарии лежат в папке `scenarios/` и задают:

- базовый конфиг;
- список отдельных прогонов;
- переопределяемые параметры для каждого прогона.

Пример:

```json
{
  "scenario_name": "scenario_1",
  "base_config_path": "../best_parameters/best_config.json",
  "runs": [
    {
      "name": "energy_high",
      "overrides": {
        "landscape_energy": 471.7427506493486
      }
    },
    {
      "name": "loyalty_low",
      "overrides": {
        "landscape_loyalty": 0.13356769638398084
      }
    }
  ]
}
```

Правила:

- `base_config_path` указывает на базовый конфиг модели;
- `runs` содержит один или несколько независимых прогонов;
- каждый прогон меняет только те параметры, которые указаны в `overrides`;
- все остальные параметры наследуются из базового конфига;
- прогоны внутри одного сценария выполняются параллельно, если это разрешает число `workers` и доступные CPU.

## Поиск лучших параметров

Если нужно заново подобрать лучший набор параметров:

```powershell
python -m program search
```

Можно уменьшить или увеличить объём поиска:

```powershell
python -m program search --trials 40 --seeds-per-trial 3
```

После поиска программа:

- сохраняет лучший конфиг в `best_parameters/`;
- сохраняет служебный файл `search_result.json`;
- сразу строит полный набор из шести графиков.

## Смысл основных параметров

- `E` — энергетическая ёмкость среды;
- `K` — лояльность среды;
- `P0` — вероятность мутации;
- `C(t)` — средний по популяции критерий выживания на каждом поколении;
- шоковые сценарии меняют не сам базовый конфиг, а внешний профиль среды во времени.
